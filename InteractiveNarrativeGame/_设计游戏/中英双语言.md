双语实现要分两层想:**技术架构层**(怎么存文本、怎么切换语言)和**内容管理层**(七门派×多案件×多结局,文本量会很庞大,怎么保证术语翻译一致)。既然你之前在FractureRealms项目上已经跑通过一套"dot-notation key + .en镜像 + L10nKeys常量类"的方案,这次可以直接复用同一套模式,减少重新踩坑的成本。

## 一、技术方案:Unity官方Localization包 vs 自建JSON方案

|方案|适合场景|优缺点|
|---|---|---|
|**Unity Localization Package**(`com.unity.localization`)|团队规模较大,需要热更新/多平台同步|官方维护、支持Smart Strings变量插值、String Table可视化管理;但学习曲线稍陡,对小团队可能过重|
|**自建JSON方案**(你在FractureRealms用过的模式)|小团队,已有成熟工作流|完全可控,复用你已验证的架构;需要自己写热更新逻辑,但你之前应该已经解决过这个问题|

考虑到你的开发习惯和已有代码资产,我倾向于建议**继续用自建JSON方案**,直接复用FractureRealms的架构:

```
Localization/
  case01_cuojia.zh.json
  case01_cuojia.en.json
  case02_guozuiyin.zh.json
  case02_guozuiyin.en.json
  ...
```

key命名沿用你之前的dot-notation习惯,针对这个游戏的分支结构可以细化成:

```
case01.faction_daoshi.stage1.dialogue01
case01.faction_daoshi.ending_success
case01.faction_daoshi.ending_fail_backlash
case01.faction_heshang.stage1.dialogue01
```

7门派 × 平均3-4阶段 × 2-3结局,单案key数量大概在150-250条之间,8案下来接近2000条——建议用`L10nKeys`常量类自动生成(可以写个简单的编辑器脚本,扫描JSON自动生成对应的C#常量,避免手写硬编码字符串key出错)。

## 二、这个游戏特有的难点:文化专有名词的术语一致性

比第一次做FractureRealms的本地化多一层麻烦——**你这次的文本里有大量中国民俗宗教专有名词,英语世界没有现成对应词**,必须自己定译并强制统一,否则同一个词在不同案子里被不同方式翻译,会让英语玩家一头雾水。建议开一份术语表(Glossary),所有涉及这些词的文本翻译前必须先查表:

|中文术语|建议英译方向|说明|
|---|---|---|
|符箓|Talisman|西方奇幻里已有对应认知,直接用|
|出马仙|Spirit Medium / 保留拼音"Chuma Immortal"+注释|西方没有直接对应概念,建议音译+首次出现时用UI提示解释,而不是强行意译丢失文化质感|
|阴阳先生|Yin-Yang Master|Yin-Yang在英语世界已有一定认知度,可直接用|
|噬恶魔|Malice Devourer / Sin-Eater|后者在西方文化里有相近典故(食罪者),可能更有代入感|
|五行八卦|Five Elements, Eight Trigrams|分开译,已是较通用的固定译法|
|心魔值|Inner Demon / Corruption(系统UI用词)|系统性数值建议用简短单词而非直译长句|

**建议做法**:术语表先行,在正式翻译任何一个案子之前先把七门派的核心术语、七个反派名字、几个核心数值系统名称定下来,存成单独一份`glossary.json`,翻译时强制引用,而不是逐案单独翻译——这一步如果跳过,后期返工成本会很高。

## 三、UI/排版适配(比纯文本翻译更容易被低估的坑)

- **英文比中文平均长30%-50%**,你的UI(尤其是对话框、技能描述、门派介绍卡片)设计时要预留弹性空间,不能按中文字数定死容器尺寸
- **TextMeshPro**支持按语言自动切换字体资源——中文建议用思源黑体/苹方类字体,英文可以单独配一套更有"玄幻感"的衬线体或定制字体,营造双语言各自的美术调性,而不是简单复用一套字体渲染两种文字
- 如果后续要做语音,双语字幕+单语音轨(比如只做中配)是成本最低的方案;全双语配音成本会显著上升,建议放到后期再评估

## 四、实际工作流建议

1. 中文剧本先全部定稿,标好所有case/faction/stage的key结构
2. 术语表先出,锁定七门派+反派+核心数值的英译
3. 导出翻译对照表(Excel/Google Sheet比直接扔JSON给译者更适合协作,可以用脚本导入导出JSON)
4. 翻译时可以用AI辅助初翻(尤其是重复性强的系统文案),但**涉及文化专有名词和情感浓度高的台词(比如渡化成功时的独白)建议人工润色**,机翻在这类文本上容易丢失语感
